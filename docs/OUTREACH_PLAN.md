# 推广与用户反馈计划

制定于 2026-11-26，之后按这份文档推进，做完一项就勾掉，有变化直接改这里。

目标有两个：让真实用户用起来，并且在各种使用场景下帮忙提意见；然后在国内把知名度做起来。先接住反馈，再放量，顺序不要反。

## 定位

**一句话：Windows 也有「屏幕使用时间」了。**

Windows 没有给成年人用的「屏幕使用时间」，这是真实存在的需求。不过统计软件时长的工具已经有了：

| 工具 | 情况 |
| --- | --- |
| Tai | 开源，中文，约 5k star，统计软件和网站的焦点时长，数据存本地 |
| ActivityWatch | 开源，跨平台，约 19k star，国外团队主导，网页界面，偏数据工具 |
| ManicTime、RescueTime | 偏专业工时记录，或走云端订阅、生产力评分路线 |

所以 GST 不靠「能统计时长」取胜，靠这几点拉开差距：

1. **像 Steam 记游戏时长那样记软件时长**：每个软件的累计小时、里程碑、成就海报，讲的是纪念感，不是自律管控。
2. **对时间分得更细**：记录、前台、后台、活跃分开算，还能找出「开着没用」的软件。
3. **隐私更严**：不记窗口标题、网页标题和文档名，不联网，不要管理员权限，不装浏览器扩展。
4. **好看**：Mica 玻璃加墨水屏的界面。
5. **海报天然适合传播**：日报海报和成就海报可以直接发到社交平台。

对外介绍时讲清楚这些区别，不贬低别的工具。

### 种子用户（20 到 30 人）

- [ ] 招募：同学和社团、V2EX 发一帖「招募内测」、小红书
- [ ] 有意覆盖不同场景：
  - 自习和写论文、写代码、设计和剪辑、办公、打游戏
  - 多显示器、笔记本合盖睡眠、开机自启
  - Win10 和 Win11 都要有
- [ ] 测试版用 GitHub 预发布版本发给他们
- [ ] 用满一周后发一份 5 题问卷：
  1. 最常打开哪一页？
  2. 哪个数字看不懂，或者不相信它准？
  3. 最想要什么功能？
  4. 会推荐给谁？
  5. 什么情况下你不再打开它？
- [ ] 找 5 个人，每人约 30 分钟，远程看着他用，让他边用边说
- [ ] 按反馈修一版，再进入第三步

### 怎么回应

- 每周固定一次整理意见，打标签：`bug`、`enhancement`、已排期、不做
- 早期尽量一两天内回复每一条
- 被采纳的建议在 CHANGELOG 和群里点名致谢
- 「不做清单」：联网上传、记录窗口标题或网页内容、设目标和打卡提醒。有人提这类需求时，按隐私承诺和「只记录，不设目标」的原则说明原因

### 节奏

1. HelloGitHub 和阮一峰周刊有审核和出刊周期，提前投。
2. V2EX、少数派、小红书、知乎、B 站**集中在一两天内**发。GitHub 趋势榜看的是短时间内 star 涨得多快，而且可以按中文筛选，分散发效果差。
3. 之后每发一个版本：在 V2EX 原帖下跟帖更新，在小红书发一张新海报，在群里发版本公告。

### 话题

- 12 月是各家出「年度报告」的季节，「我的 2026 软件时长」是现成话题。只是个可选想法，不改动已定的路线图。
- 海报角落可以带上软件名和仓库地址，每张被转发的海报都是一次推广。

## 底线

- **不刷 star。** GitHub 会清理刷来的星，开发者圈子一旦发现，口碑就毁了。
- 不发广告式的硬推，只在相关的帖子和问题下出现。
- 推广内容和软件本身一样遵守隐私承诺：示例截图用示例数据，不晒真实的软件路径和个人信息。
