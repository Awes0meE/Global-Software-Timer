# 网站时长设计草案

状态：草案，产品问题已全部确认（2026-11-26），暂不开发；界面样稿和动工前的技术验证还没做。对应版本 v0.6.0，v0.5.x 留给时间轴。参照：Tai 1.1.0.7 的网页统计实现（MIT，`Planshit/Tai`），只借思路，不搬代码。

## 目标与范围

在浏览器拿着前台焦点时，把 tracker 已认可的秒数再细分到「当前是哪个网站」。只记网站的主机名，例如 `bilibili.com`，不记页面、路径、参数和标题。功能默认关闭，用户主动开启后才装扩展、才开始记录。

| 做 | 不做 |
| --- | --- |
| Chrome 和 Edge 的 MV3 扩展「GST 网站时长」 | Firefox、Brave、Vivaldi 等其他浏览器（以后按需加） |
| 原生消息（Native Messaging）本机通道，注册在 HKCU，不要管理员权限 | 本机端口、WebSocket、HTTP 服务 |
| 在 tick 的同一个事务里按站点记前台秒数和活跃秒数，schema 3 → 4 | 改现有日汇总、会话、时间轴表的记法 |
| 新页面 `网站`：按日浏览、站点表、今日分布、不记录的网站 | 网站进统计页、成就页、海报（v1 不做） |
| 不记录的网站名单、删除单个站点或全部网站记录 | 记完整网址、路径、查询参数、页面标题、网页图标地址 |
| 当日网站 CSV 导出，名单进设置导出 | 联网取网站图标、遥测、上传 |
| 网站图标：扩展从浏览器本地的图标缓存读出 PNG 交给 GST | 网站图标进海报、导出 |
| 无痕窗口一律不记 | 读浏览器地址栏（UI Automation）、注入页面脚本 |

## 隐私边界

这项功能会让 GST 第一次知道「用户上过哪些网站」。域名本身也可能敏感（医院、求职、成人网站），所以边界要比 Tai 严：

1. **截断发生在浏览器里。** 扩展拿到标签页网址后当场取主机名，网址、路径、参数和标题从不离开浏览器。GST 收到的消息里只有主机名。
2. **默认关闭，主动开启。** 第一次开启时弹窗写清楚记什么、不记什么；关闭后停止记录，已有数据保留，可一键清空。
3. **无痕不记。** 扩展清单写 `"incognito": "not_allowed"`，扩展根本不在无痕窗口里运行。
4. **不联网。** 扩展不发任何网络请求、没有内容脚本、不申请站点权限；GST 不下载网站图标。图标来自浏览器已经缓存在本机的图标，读取不触发网络请求。
5. **只有自家扩展能说话。** 原生消息由浏览器按扩展 ID 校验，本机不开端口。GST 和通道进程之间的命名管道只允许当前用户连接，并核对对方进程路径。Tai 的做法是在 8908 端口开 WebSocket、不做任何校验，任何网页都能连上来写假数据，这里不学。
6. **GST 不信任扩展发来的内容。** 主机名在 GST 里重新校验和归一，不合规的直接丢弃。

开启这项功能需要先改 `AGENTS.md` 的隐私规则：在「不收集浏览记录」下加一条例外，即「用户主动开启后，只记网站主机名的停留时长」。`PRIVACY.md` 同步。

## 整体结构

```text
浏览器（Chrome / Edge）
  └─ GST 扩展（service worker）
       │ 只在状态变化时发：{当前站点主机名 | 无, 本窗口是否有焦点}
       ▼  原生消息（stdin/stdout，浏览器负责启动和校验扩展 ID）
GST.exe 通道模式（由浏览器拉起的短进程，不开窗口，不碰数据库）
       │  命名管道，只允许当前用户
       ▼
GST 托盘主进程：管道服务线程 → 共享的「各浏览器当前站点」状态
       ▼
tracker tick（每 5 秒）：前台是浏览器时，把本 tick 的秒数记给当前站点
```

关键点：**扩展只报状态，不报时长。** 时长全部由 GST 的 tracker 计算，和软件前台时长共用同一套断档、回拨、空闲判定，所以同一浏览器某一天所有站点的前台秒数之和不会超过它当天的前台秒数。扩展没装、没连上或者浏览器不在前台时，这段时间就不分给任何站点。

## 浏览器扩展

源码放在仓库 `browser-extension/`，Chrome 和 Edge 共用一份。

清单要点：

```json
{
  "manifest_version": 3,
  "name": "GST 网站时长",
  "permissions": ["tabs", "nativeMessaging", "favicon"],
  "incognito": "not_allowed",
  "background": { "service_worker": "service-worker.js", "type": "module" },
  "minimum_chrome_version": "116"
}
```

- `tabs` 权限是读取标签页网址的唯一方式。安装时浏览器会提示「读取您的浏览记录」，商店说明和开启弹窗里要正面解释。
- `favicon` 权限让扩展能读浏览器本地的网站图标缓存（MV3 的 `_favicon` 地址，Chrome 104 起），用来给 GST 提供真实图标。
- 不申请 `host_permissions`，没有 `content_scripts`，没有 `web_accessible_resources`。
- 清单里带 `key`，固定开发版扩展 ID，便于本地加载调试。

行为：

1. 启动时调用 `chrome.runtime.connectNative("com.globalsoftwaretimer.web")`。端口开着时浏览器会保持 service worker 存活（Chrome 105 起）。
2. 监听 `tabs.onActivated`、`tabs.onUpdated`（只看 `url` 变化）、`windows.onFocusChanged`。任一事件发生后，算出「有焦点窗口的活动标签页的主机名」；结果和上一次不同才发消息。
3. 主机名只取 `http:` 和 `https:` 网址的 `URL.hostname`；`chrome://`、`edge://`、`file://`、扩展页、新标签页一律算「无站点」。
4. 端口断开后按 5 秒、10 秒、30 秒、60 秒退避重连。不缓存、不补发：状态只有「现在」这一刻有意义。
5. 图标两态：已连接、未连接。不显示弹出页。

消息格式（扩展 → GST），UTF-8 JSON，不超过 512 字节：

```json
{ "v": 1, "type": "state", "host": "space.bilibili.com", "focused": true }
```

`host` 为 `null` 表示无站点；`focused` 是这个浏览器配置文件有没有拿着焦点窗口。同一浏览器开了多个配置文件时，每个配置文件各有一个扩展实例和一条连接，靠 `focused` 区分。

### 网站图标

1. 扩展启动时先读一次一个不存在的地址的图标（`_favicon/?pageUrl=https://gst.invalid/&size=32`），得到浏览器的「默认地球图标」，记下它的字节作为对照。
2. 某个主机名在本次扩展会话里第一次出现、页面加载完成后，扩展用当前标签页的网址读 `_favicon/?pageUrl=<网址>&size=32`。完整网址只在浏览器内部用来查缓存，发给 GST 的消息里没有网址。
3. 读到的字节和默认地球图标相同（浏览器还没缓存这个网站的图标），就不发；下次再出现时再试。
4. 读到真实图标就发一条图标消息。同一会话里每个主机名最多发一次。

```json
{ "v": 1, "type": "icon", "host": "space.bilibili.com", "png": "<base64>" }
```

图标消息上限 16 KB，状态消息上限仍是 512 字节。

## 本机通道

### 注册

开启功能时，GST 写入当前用户注册表，关闭时删除：

- `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.globalsoftwaretimer.web`
- `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.globalsoftwaretimer.web`

默认值指向 `%LOCALAPPDATA%\com.globalsoftwaretimer.app\native-host.json`：

```json
{
  "name": "com.globalsoftwaretimer.web",
  "description": "全局软件计时器 网站时长",
  "path": "<GST 主程序的完整路径>",
  "type": "stdio",
  "allowed_origins": [
    "chrome-extension://<Chrome 商店 ID>/",
    "chrome-extension://<Edge 商店 ID>/",
    "chrome-extension://<开发版 ID>/"
  ]
}
```

`path` 取运行时的 `std::env::current_exe()`，不写死文件名。GST 每次启动时，如果功能开着，就重写一遍这个文件，因为升级后安装路径可能变化。NSIS 和 MSI 两种卸载程序都要删掉这两个注册表项和这个文件。

### 通道模式

不另做一个可执行文件，复用 GST 主程序。浏览器拉起它时第一个参数是调用方来源 `chrome-extension://<ID>/`。`main.rs` 在进入 `run()` 之前看到这个参数，就转入通道模式：

- 不建窗口、不启动 tracker、不做单实例检查、不打开数据库。
- 从 stdin 读「4 字节长度 + JSON」帧。超过 16 KB 的帧、解析失败的帧直接丢弃；状态消息超过 512 字节也丢弃。
- 连接 GST 主进程的命名管道，把每条状态原样转发过去，转发时附上浏览器主进程的 PID（取自本进程的父进程）。
- 管道连不上（GST 没运行）就每 5 秒重试，只保留最新一条状态，连上后先发这一条。
- stdin 关闭（浏览器关了、扩展被停用）就退出。

### 命名管道

- 名称：`\\.\pipe\com.globalsoftwaretimer.web-<当前用户 SID>`。
- 安全描述符只允许当前用户访问，设置 `PIPE_REJECT_REMOTE_CLIENTS`。
- 主进程用 `GetNamedPipeClientProcessId` 取得对方 PID，核对对方可执行文件路径就是 GST 自己，不符就断开。
- 每条连接每秒最多处理 20 条消息，超出的丢弃。

### 主进程里的共享状态

管道服务线程维护一张表：连接 ID → 浏览器 PID、主机名、`focused`、更新时间。连接断开就删掉对应条目。tracker tick 只读这张表。

### 图标入库

图标消息不进 tracker tick，由管道服务线程直接处理：

1. 主机名按「站点归一与校验」处理，不合规就丢弃；在「不记录的网站」名单里也丢弃。
2. base64 解码后交给现有的 `image` 库解码，只接受 PNG，宽高 16 到 64 像素。解码失败就丢弃。
3. 重新编码成 32×32 的 PNG，丢掉原图里的全部元数据。
4. 写进现有图标缓存目录下的 `sites\`（`%LOCALAPPDATA%\com.globalsoftwaretimer.app\icons\sites\`），文件名是主机名的 SHA-256。已有同名文件、并且不到 30 天，就不重写。
5. 界面通过现有的 `gsticon` 协议读取，沿用它只对本应用来源发 CORS 头的规则。90 天没被读到的图标文件随现有清理一起删掉。

主域名那一行用哪个图标：主域名本身（或 `www.` 去掉后的它）有图标就用它，否则用这个主域名下今日活跃最长的子域名的图标，都没有才用首字母方块。

## 计时规则

在 `run_tracker_tick_with_foreground` 里，算出 `foreground_app_id` 之后：

1. 前台软件的身份不是浏览器（v1 只认 `chrome.exe` 和 `msedge.exe`），就不记站点。
2. 在共享状态里找浏览器 PID 等于前台 PID、并且 `focused = true` 的连接；有多条时取更新时间最近的那条。找不到就不记站点。
3. 主机名为 `null`，或者在「不记录的网站」名单里，就不记站点。
4. 否则对 `credited_days` 拆出的每一段 `seconds`：站点前台秒数加 `seconds`，站点活跃秒数加 `active_seconds`（和机器空闲判定一致）。

和软件页的口径对齐：前台秒数不受空闲判定影响，活跃秒数受影响。以后「有声音算活跃」上线后，网站的活跃秒数自动跟着变，不需要扩展参与。

写入和现有日汇总在同一个 savepoint 里，tick 失败时一起回滚。

## 站点归一与校验

GST 收到主机名后按顺序处理，任何一步不合规就当作「无站点」：

1. 长度 1 到 253，只含 `a-z`、`0-9`、`.`、`-`（扩展端的 `URL.hostname` 已经把大写转小写、把中文域名转成 `xn--` 形式）。
2. 去掉开头的 `www.`。
3. IP 地址和 `localhost` 保留原样，端口在扩展端就已经去掉。

存储保留主机名：`space.bilibili.com` 和 `live.bilibili.com` 各记各的。界面按主域名合并（2026-11-26 已定）：

- 主域名用公共后缀表算出，例如 `space.bilibili.com` → `bilibili.com`，`news.bbc.co.uk` → `bbc.co.uk`。用 Rust 的 `psl` 一类库，公共后缀表编译进程序，不联网更新。
- 表里一行是一个主域名，时长是它所有子域名之和；点开这一行，列出各个子域名。只有一个子域名的主域名不显示展开键。
- IP 地址和 `localhost` 不合并，各自一行。
- 「不记录的网站」名单按主域名匹配：加了 `bilibili.com`，它的所有子域名都不记。
- 主域名在读取时现算，不存进数据库。公共后缀表随版本更新时，旧数据不用迁移。

## 存储：schema 3 → 4

沿用 `storage.rs` 的约定：日期是本地 `YYYY-MM-DD` 文本，时刻是 UTC RFC 3339 文本，外键开启。

```sql
CREATE TABLE IF NOT EXISTS web_sites (
    site_key TEXT PRIMARY KEY,
    first_seen_at TEXT NOT NULL,
    last_seen_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS daily_site_usage (
    usage_date TEXT NOT NULL,
    site_key TEXT NOT NULL REFERENCES web_sites(site_key),
    browser_identity_key TEXT NOT NULL REFERENCES software_identities(identity_key),
    focused_seconds INTEGER NOT NULL DEFAULT 0,
    active_seconds INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (usage_date, site_key, browser_identity_key)
);

CREATE TABLE IF NOT EXISTS ignored_web_sites (
    site_key TEXT PRIMARY KEY,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

- `site_key` 是归一后的主机名。
- 「不记录」名单的条目不要求在 `web_sites` 里出现过，可以先加名单再访问。
- 开关存在 `app_settings`：`web.enabled`，默认 `false`。
- 迁移只建表，不动旧表；按现有迁移测试的做法，用 schema 3 的副本测升级。
- 体量：每天约 50 个站点、2 个浏览器，一年不到 4 万行。

站点和时间轴的关系：v1 不往 `timeline_segments` 里加站点列，时间轴页先不显示网站。需要时再单独出稿。

## 设置

`设置` 新增「网站时长」一组：

- `记录网站时长` 开关，默认关。第一次打开时弹窗说明记什么、不记什么，按 `开启` 才生效。
- Chrome、Edge 各一行：状态 `已连接` / `未连接`（看共享状态里有没有这个浏览器的连接），旁边是 `安装扩展` 键，用默认浏览器打开对应的商店页面。打开网页由浏览器完成，GST 自己不联网。
- `清空网站记录`：确认后删除 `daily_site_usage` 和 `web_sites` 的全部行，以及 `icons\sites\` 下的全部图标，不能撤销。
- 关闭开关：删除注册表项和 `native-host.json`，停止管道服务，已有数据保留。

说明文字放进 `?` 气泡和开启弹窗，不写小字。

## 技术验证（动工前先做）

1. Chrome 和 Edge 拉起的通道进程，父进程 PID 是否就是前台窗口所属的浏览器主进程 PID（包括 Edge 启动加速、多窗口、多配置文件）。不是的话，退回到按 `chrome.exe` / `msedge.exe` 身份匹配。
2. 发布版 GST 是 Windows 子系统程序，确认它在通道模式下能正常读写浏览器传来的 stdin/stdout。不行的话，改成单独打包一个控制台小程序。
3. `connectNative` 端口开着时，service worker 长时间不被回收；浏览器休眠、唤醒后能自动重连。
4. `_favicon` 在 Chrome 和 Edge 上都能用；读取时确实不发网络请求（用开发者工具的网络面板看）；`favicon` 权限安装时有没有额外提示；没缓存时返回的默认图标能否用字节对照识别出来。
5. 商店审核：Chrome 应用商店需要一次性 5 美元开发者注册费，Edge 加载项免费；两边都要求隐私政策链接，可以指向仓库里的 `PRIVACY.md`。
