v0.4.2（2026-11-25 发布）的行为，设计见[规格](./superpowers/specs/2026-11-24-v042-date-browsing-and-exports-design.md)：

- **看哪一天**：`App` 持有概览和后台共用的查看日期，不保存，重启回到今天。看今天时页面可见就轮询，过本地午夜自动换到新的一天（窗口重新可见时再核对一次）；看往日时只读一次、不轮询，晚到的别一天的回答丢弃；切换日期后，新日期回来之前旧数字变暗并带 `aria-busy`，读取失败时只显示警告。后端回答 `day_invalid_date`（日期格式错或在今天之后）时退回今天。侧栏“正在记录”灯始终读今天的实时采样。
- **日期键与日历**：`‹ 日期 ›` 一组键，看往日时右边多一个“今天”键。日历是 react-day-picker 10.0.2 的普通日期选择器（周一在前、zh-CN），不显示按日数据；可选范围来自只读命令 `get_calendar_summary`，只返回 `today` 和 `data_start_date`（`daily_system_usage` 的最早日期）。这次读取失败时 5 秒后重试，之后每次加倍，最长 60 秒，直到成功（成功读到 `data_start_date` 为空也算成功）。统计页“自定义”区间用同一个日历的区间模式。
- **导出**：概览“导出日报”、软件“导出软件清单”、后台“导出后台记录”、统计“导出报表”（区间汇总）各存一个 CSV，成就页没有导出键；设置页“迁移与备份”菜单有导出设置（JSON）、导入设置…、备份全部数据（DB）。CSV 由前端拼文本，Rust 写入时加 BOM；RFC 4180 引号、CRLF，以 `=` `+` `-` `@`、TAB、CR 开头的单元格前加 `'`，时长两位小数小时，不含程序路径。文件名和列见规格 D、E 节，其中统计 CSV 的列为软件名称、进程名、排名、焦点、窗口开着、开着没用、打开次数、平均单次、最长单次。后台 CSV 每天都写当日峰值（今天的峰值含最近一次实时采样），不写当前 CPU 和状态。
- **写文件**：保存和打开对话框在 Rust 里跑（`tauri-plugin-dialog` 2.7.3，`spawn_blocking`），默认目录是“下载”，前端没有对话框或文件系统权限。CSV 和设置文件先写同目录的 `.gst-export-<uuid>.tmp`，再改名盖到目标；备份先 `VACUUM INTO` 同目录的 `.gst-backup-<uuid>.tmp` 再改名；任一步失败都删掉临时文件，原有的同名文件不受影响。目标不能是正在使用的数据库或它的 `-wal` / `-shm` / `-journal` 文件（`export_target_is_database`）。保存成功弹“已保存”轻提示和“在文件夹中显示”键，`reveal_saved_file` 只对本次运行里保存过的路径用 Windows 目录下的 `explorer.exe /select` 打开；取消什么都不做；失败弹“保存失败”。轻提示约 6 秒消失，鼠标停在上面或键盘焦点（`:focus-visible`）在里面时暂停，点击留下的焦点不算。
- **设置文件**：`kind = "gst-settings"`、`schema = 1`；`settings` 只写用户选过的主题、时长格式和关闭行为，没选过的为 `null`；特别关注、隐藏两个名单每项是身份键的 `sha256:<hex>` 摘要、显示名和进程名，不写身份键本身（它含安装路径和 Windows 用户名）。不含开机自启、使用记录和程序路径。导入：文件不超过 1 MB（`settings_import_too_large`），`kind` / `schema` 不对或读不出来是 `settings_import_invalid`，未知字段忽略；预览存在 `AppState` 里、导入 id 只能用一次（`settings_import_expired`）。名单先按摘要、再按进程名（不分大小写，同名取最近见过的身份）匹配本机身份，对不上的计入“本机没有的软件”，本机已在另一名单或文件里两边都有的计入“已在另一列表”，都跳过；只加不删，设置和名单在一个事务里写入。文件里的设置只要本机还没选过或选得不同就写入，即使等于当前默认值（这样导入“最小化到后台”后第一次关闭窗口不再询问）；预览只列显示值会变的设置。导入确认框打开时页面其余部分 `inert`，轻提示除外（v0.4.3 起画在遮罩上面，见下）。
- **往日页面**：口径见下表“往日概览”“往日后台”。概览往日隐藏“正在运行”，当日分布占满右栏并在最后一行后结束；后台概况条往日四格（当日 CPU 时间、当日出现、当日后台时长、峰值内存），表格去掉当前 CPU 和状态列。后台墨水屏条加高到 108px，数字仍是 36px。

v0.4.3（2026-11-25 发布）的行为，设计见[规格](./superpowers/specs/2026-11-25-v043-posters-and-reports-design.md)：

- **导出菜单**：概览“导出日报”是菜单键：日报海报（PNG）、当日明细（CSV，即 v0.4.2 的日报 CSV）。统计“导出报表”是菜单键：区间汇总（CSV）、每日明细（CSV），两者都读只读命令 `get_statistics_export`，跟随页面的区间和“包含隐藏软件”。区间汇总比 v0.4.2 多两列“后台(小时)”“使用天数”（当天焦点 ≥ 300 秒算一天），列出区间内所有有焦点、窗口或后台时间的软件，不只前 20；有排名的行在前、按排名排，其余按导出顺序接在后面。成就页加“导出成就”键（PNG 标签，无下拉），打开“成就海报”玻璃对话框选一款软件；没有软件到达里程碑时键为 `aria-disabled`、变暗、键身变平，悬停提示“暂无里程碑”；里程碑列表读取失败后再点一次会重读，仍失败提示“无法读取成就”。
- **海报**：1080×1440 PNG，前端用 modern-screenshot 4.7.0 截图（按需加载），字体为打包的 Inter 与思源黑体子集；保存走 Rust 命令 `save_binary_export`（原始字节、32 MiB 上限、PNG 签名检查），流程同 CSV 的“已保存 / 保存失败”。PNG 去掉截图带的 192 DPI `pHYs` 块，文档软件按像素尺寸摆放。图标经 `fetch` 读成 data: URL，`gsticon` 协议只对本应用来源（安装版 `http://tauri.localhost`，`tauri dev` 时另加 `http://localhost:1420`）回 CORS 头；读不到时画首字母方块。
- **对话框与轻提示**：玻璃对话框（导入设置、成就海报、首次关闭选择）打开时页面其余部分 `inert`，轻提示除外：它带 `data-modal-keep`，仍是实时播报区域，并画在遮罩上面（z-index 45，遮罩 40，? 气泡 50），所以海报保存失败时对话框不关、“保存失败”看得清；焦点陷阱让 Tab 到不了它。首次关闭选择框也是模态框，能叠在成就海报对话框上：上层框接管 Tab、焦点和 Esc（Esc 不关它），选完后焦点回到下层对话框。

v0.4.4（2026-11-26 发布）的行为，设计见[规格](./superpowers/specs/2026-11-26-v044-personalization-and-data-design.md)：

- **设置页**：自上而下是本机状态、运行（开机自启动、关闭窗口时最小化到后台、启动时打开）、显示（显示分钟数、每周起始日、文字大小、动画速度、减少动画）、外观（主题、主题色、墨水屏配色）、数据（数据文件夹、从备份恢复）、隐私。页面组件从 `App` 移到 `src/components/SettingsPage.tsx`。设置页有侧栏、本机状态屏和五组面板，共 7 个模糊层，比其他页的上限 6 多 1 个；1440×900 下同屏只看得到 5 个，窗口高到约 1300 CSS px 才 7 个全在屏上。这是唯一的例外，由 `glassSurfaces.test.tsx` 固定。
- **存储**：五个新键 `ui.accent`、`ui.eink`、`ui.week_start`、`ui.start_page`、`ui.reduce_motion` 存在 `app_settings` 表里，schema 不变；一个设置命令 `set_ui_preference(key, value)` 校验后写入，未知的键或值返回 `ui_preference_unknown_key` / `ui_preference_invalid_value`。设置文件（仍为 `gst-settings`、schema 1）多带这五项，旧文件照常导入，未来版本的未知取值丢掉；导入确认框的标签见规格 I 节。
- **首帧缓存**：`main.tsx` 在渲染前调用 `paintInitialAppearance()`，从 localStorage `gst.appearance` 读出主题色 id、上一次用过的跟随 Windows 色对（只收 `#rrggbb`）、墨水屏配色和减少动画，设置根元素的 `data-accent`、`--user-accent-light` / `--user-accent-dark`、`data-eink` 和 `data-motion`，跟随 Windows 的 `--user-glow-*` 按缓存的色对现算（透明度本身不缓存）；`gst.startPage` 缓存启动页。SQLite 仍是唯一的真值，每次读取、保存、导入和读到 Windows 强调色后都重写缓存。
- **主题色**：8 种，默认 `blue`。选蓝时去掉行内的 `--user-accent-*`，光晕就是 v0.4.3 的 `--glow`，与 v0.4.3 逐像素一致；其他选择用强调色拼出三个光晕，透明度按选择、主题和光晕分别取不超过样稿 45/26/30（浅）、50/24/28（深）、在三个光晕中心上都通过对比度检查的最大整数百分比（搜索在 `src/glow.ts`），光晕 1 仍比样稿淡，表格在 `src/styles.css`（也抄在 `DESIGN.md` 和规格 B 节）；跟随 Windows 按调整后的颜色现算，写成行内 `--user-glow-*`，读不到时用样式表的保守退路值。跟随 Windows 由只读命令 `get_windows_accent` 读 `AccentPalette`（浅色取 AccentDark1，深色取 AccentLight2），没有时读 `DWM\AccentColor`，都读不到返回 `null` 并退回蓝的颜色（光晕仍按强调色拼）；前端 `src/accent.ts` 在 OKLCH 里只调明度、保留色相和彩度，直到满足预设的对比度规则。选跟随 Windows 时在读取设置后和窗口每次重新可见时读，只认最近一次请求；选别的颜色时，设置页打开时只读一次，用来画跟随 Windows 色点，屏上别处不变。
- **墨水屏配色**：5 套，默认 `aurora`（即 v0.4.3 的样子）。每套按主题设齐 11 个 `--eink-*` token，选择器按主题分开（`:root:not([data-theme="dark"])[data-eink]` / `:root[data-theme="dark"][data-eink]`）。日历焦点环在每套纸面上对 8 种主题色都不低于 3:1，所以不需要改用 `--eink-ink` 的退路（`contrast.test.ts` 逐项检查）。海报不跟着变。
- **每周起始日**：`WeekStartContext`（`src/weekStart.ts`，周日 = 0、周一 = 1，默认 1）由 `App` 提供，只影响前端显示，后端命令不加参数。跟着变的正好五处：日期日历、统计“本周”（`(今天星期 - 起始日 + 7) % 7`）、成就热力图的表头和前导空格、走纸记录仪中密度的周标记、软件页“这周X / 上周X”。星期名称、工作日 / 周末、海报、CSV 和统计对比区间不变。
- **启动时打开**：选项取自侧栏的可用页面（不含设置，时间轴开放后只需加一处）；`settings`、`timeline` 和未知值都当作概览。只在进程启动时生效，从托盘或第二次启动唤出窗口不换页。首帧按 `gst.startPage` 渲染并预热那页的懒加载块；设置读回后刷新缓存，只有存的页和缓存不同、且用户还没切过页时才切换一次；改设置或导入设置只保存，不跳页。
- **减少动画**：`reduce` 时根元素带 `data-motion="reduced"`；`@media (prefers-reduced-motion: reduce)` 不变，旁边一块 `:root[data-motion="reduced"]` 的同样规则，由对齐测试保证两块一致。`system`（默认）时仍跟随 Windows。
- **单选组的键盘**：启动时打开、每周起始日、主题（分段选择器）和主题色、墨水屏配色共用 `useRovingRadios`：每组一个 Tab 停点，方向键、Home、End 移动并选中，值没变不保存。强制颜色模式下选中的色点和色块是 `Highlight` 环，焦点在它外面再加一圈 6–8px 的 `Highlight`（中间 `Canvas` 间隔）。
- **打开数据文件夹**：命令 `open_data_folder` 用应用自己的数据目录（不收页面传来的路径），走现有的 `explorer_path()`、`raw_arg` 引号和 `.spawn()`；失败提示“无法打开数据文件夹”。没有新插件，也不改权限。
- **从备份恢复，挑选与检查**：“选择备份…”在 Rust 里打开原生对话框（过滤“GST 数据备份”：`db` / `sqlite3` / `sqlite`，从“下载”开始），`pick_restore_backup` 在 `spawn_blocking` 里检查：拒绝正在使用的库和它的旁文件、恢复用的各个文件名，以及数据文件夹里 `backups\` 以外的文件；要求 SQLite 文件头和足够的剩余空间；把文件复制成数据文件夹里的 `.gst-restore-<uuid>.tmp`，去掉副本的只读属性，再只在副本上检查（`trusted_schema=OFF`、defensive、不许有触发器和视图、`quick_check`、按 `user_version` 要求表），跑 `Store::migrate()`、改成 `journal_mode=DELETE`。预览只用一次（`restore_id`），再选或取消就删掉之前的副本。确认框打开时 `aria-describedby` 指向两段提醒文字（`restore-dialog-copy`），事实行不算在描述里；检查期间“选择备份…”带 `aria-busy` 和 `aria-disabled`，变暗但仍可聚焦。
- **从备份恢复，换库**：`apply_restore` 把副本改名为 `global-software-timer.sqlite3.restore-pending`，正常退出（`tracker.shutdown()` 照常跑），退出后用 `--after-restore=<pid>` 重新启动自己（不用 `AppHandle::restart`）。新进程先等旧进程退出（约 15 秒），再重试单实例锁，然后在 `setup` 里、任何连接打开之前跑 `run_startup_swap`：把当前库 checkpoint 成单文件、改名为 `.before-restore`，删掉留着旧名字的 `-wal` / `-shm`，把 pending 改成正式库，打开成功后把 `.before-restore` 移到 `backups\GST-恢复前-YYYY-MM-DD-HHMMSS.db`，只留最新 3 份（刚移进去的那份总是留下）；打开失败就把恢复的文件改成 `.restore-failed`、换回原库。每一步都能在崩溃后接着做，改名重试约 10 × 200ms，所有文件都在数据文件夹里。重启后轻提示“已从备份恢复”或“恢复没有完成，已保留原来的数据”（`get_restore_status`，只报一次）。
- **从备份恢复，卡住时**：pending 既换不上去、也改不成 `.restore-failed` 或删不掉时，不打开任何库（打开正式库名会建出空库，或下次启动会把报告为已退回的恢复又换上去），弹出启动错误框：“从备份恢复没有完成：数据文件暂时无法移动。请关闭占用数据文件夹的程序（如杀毒或备份工具）后重新打开全局软件计时器，现有数据不会丢失。”后面附数据文件夹路径；下次启动接着做完。
- **图标路径**：`IconStore::url_for` 和 `storage.rs` 的 `executable_path_score` 只对字母盘符上的绝对路径（`C:\…`、`C:/…`、`\\?\C:\…`，`src-tauri/src/local_path.rs`）碰文件系统；UNC（`\\host\share`、`//host`）、`\\?\UNC\`、`\\.\` 和相对路径一律不读，恢复来的库里存的路径也一样。所以从网络共享运行的软件没有图标，显示首字。
- **预览**：`?accent=`、`?eink=`、`?weekstart=sun`、`?startpage=`、`?motion=reduce` 只改模拟的存储值；`?startpage` 不会打开那一页（模拟在回答 `get_app_settings` 之前替用户点一下概览，所以 `App` 的一次性切换不触发），要看别的页仍用 `?page`。`?restore=ok|invalid|newer|live|space|fail`、`?restorestatus=restored|rolled_back` 驱动恢复的模拟，`?dialog=restore`（配 `?page=settings`）直接打开恢复确认框，`?export=fail` 也让打开数据文件夹失败。`get_windows_accent` 返回示例色对 `#0067c0` / `#4cc2ff`。

| 查询连接 | 概览和软件页使用独立只读连接及一致性读事务；仅复制运行状态时短暂持有 tracker 锁。查询不再写身份缓存。终身会话区间合并与历史兼容逻辑保留。 |
| 界面刷新 | 页面可见时轮询，document 隐藏后停掉轮询，恢复可见时刷新；不积压计时器请求。软件页的过期成功/失败响应不能覆盖用户操作后的新列表。 |
| 发布脚本 | 检查或打包命令返回非零状态时立即停止，不再继续复制旧安装包；两条失败路径已有自动回归测试并接入本地 check 与 CI。 |

## 统计口径

| 指标 | 定义 |
| --- | --- |
| 概览软件运行 | 被分类为可记录的非辅助进程拥有任务栏式窗口或被识别为托盘软件时建立会话，按会话区间合并计算。不是所有进程存活时间。 |
| 最常用 | v0.2.3 起取今日活跃时长最多的软件；今天没有活跃时长时取今日运行时长最多的软件；今天没运行过则为空。台账仍按累计时长排序。 |
| 前台运行 | 符合条件的进程拥有任务栏式应用窗口（可见、无可见所有者、非工具/不激活/穿透浮层、未被自身隐藏、非零尺寸），不要求键盘焦点；多个软件可同时处于此状态。UWP 框架窗口归属到其承载的应用进程。 |
| 托盘运行 | 无任务栏窗口，但可执行文件登记在 `HKCU\Control Panel\NotifyIconSettings`（Win11）且进程在当前用户会话中。与前台运行一样建立运行会话；软件页计入窗口外（后台）时长。注册表会记住曾经显示过的图标，因此是近似判断；Win10 无此数据，退回原行为。 |
| 后台运行 | 已知可执行文件仍存在，但既无任务栏窗口也无托盘图标，或只剩辅助进程；不建立运行会话，软件页按身份累计。 |
| 后台页 | 非 Windows 系统进程中既无窗口也无托盘图标者，按软件族分组；由可见软件（含经辅助进程）启动的子进程归属该软件、不列出。每日记录后台时长、CPU 核心秒、内存峰值与进程数（`daily_background_usage`，库版本 2），并显示最近一次采样的实时 CPU/内存。 |
| 概览今日活跃 | 机器键鼠空闲不超过五分钟时的计入秒数；概览软件活跃再归属到已识别的前台 PID。 |
| 软件页活跃 | 已识别软件拥有 Windows 前台焦点时的计入秒数，不受键鼠空闲门槛影响。 |
| 软件身份 | 按去版本号的路径族归并：商店应用按包族合并，版本号目录与哈希目录忽略。启动时把旧的逐版本身份及其汇总、标记合并，单日合并结果不超过 24 小时。 |
| 隐藏软件 | 继续记录，过滤默认软件汇总、排行与分布，不扣除机器级总数。 |
| 历史兼容 | 软件页保留拆分记录开始前的会话回退；新会话在观察时即写入拆分边界，避免零计入恢复或小数秒采样触发重复累计。旧数据缺失的焦点/后台历史不能凭空重建。 |
| 往日概览（v0.4.2） | `get_dashboard_summary(date)`：日期为空或等于今天走实时路径；往日的日界由 `local_date_bounds_in` 给出（夏令时没有午夜的日子也对），今天的实时路径也改用它。往日读数取那天的 `daily_system_usage`；只列那天运行过或活跃过的软件，“当日”是那天的运行时长，“当日活跃”是那天的活跃时长，“累计”截到那天结束；没有实时状态（都算未运行）；隐藏软件照旧不列。数据起点之前的日子返回空摘要。两个摘要都返回 `usage_date`（所请求的那天）和 `is_today`。 |
| 往日后台（v0.4.2） | `get_background_page_summary(date)` 往日只读 `daily_background_usage` 存下的行，不叠加实时采样：进程数、内存取当日峰值，`cpu_percent` 为空，都不在运行。概况条的“峰值内存”是各软件当日峰值之和，这些峰值不一定同时出现，口径写在“后台进程”说明气泡里。往日表格的排序列被隐藏时退回默认排序。 |
| 统计页机器数字 | 每日趋势、活跃率、环比，以及作息里的工作日 / 周末日均活跃和日均开机时长，读 `daily_system_usage` 的记录、活跃（五分钟键鼠空闲门槛）与开机时长（`tracker_uptime_seconds`）。每日趋势和工作日 / 周末日均活跃把区间内没有数据的日子补 0；日均开机时长只除以有记录（记录时长大于 0）的日子。这两条规则从 v0.4.1 起写在作息标题旁的 ? 气泡里，不再印在格子下。不受隐藏软件影响。 |
| 作息最早 / 最晚记录 | 不读 `daily_system_usage`：取 `daily_software_runtime_usage` 中当天有窗口（`foreground_seconds > 0`）的行的最早 `first_recorded_at` 和最晚 `last_recorded_at`，再对区间内有值的日子取本地时间中位数。只算有窗口时间的日子；软件明细起点之前的日子没有值；隐藏软件始终计入，“包含隐藏软件”开关不过滤。 |
| 统计页软件数字 | 区间排行按软件焦点（`daily_software_focus_usage`）排名，与软件页活跃同一口径；保留焦点或窗口大于 0 的软件，最多 20 个，同分按显示名。名次与上一个等长区间比较，上一区间不可比时不标名次变化和“新上榜”。 |
| 开着没用 | 只算有任务栏窗口的时间（`daily_software_runtime_usage.foreground_seconds`），不算托盘和后台时间。区间内窗口不少于 5 小时、焦点低于窗口的 5% 才上榜，按窗口减焦点的时长排序。 |
| 统计页会话 | `usage_sessions` 经身份成员表归到软件身份，按开始时间的本地日期落入区间；已关闭会话用记录的时长，未关闭会话用最后心跳减开始时间。会话包含托盘运行。 |
| 区间与软件明细起点 | 数据起点取 `daily_system_usage` 的最早日期，软件明细起点取 `daily_software_runtime_usage` 的最早日期（本机为 2026-05-29 和 2026-06-18）。自定义区间最长 366 天，不早于数据起点。上一区间早于数据起点时机器对比显示“无对比”，早于软件明细起点时排行不比名次。明细起点之前的日子标“无软件明细”，软件数字不计入，也不当作 0。 |
| 热力图与连续天数 | 按机器活跃（`daily_system_usage.active_seconds`）。当天活跃不到 5 分钟按“没用”算，只为过滤开机看一眼的噪声，不是目标。连续天数和“活跃最长的一天”按全部历史，不受热力图范围（90 / 180 / 365 天）和隐藏开关影响；今天还没满 5 分钟时，当前连续从昨天往回数。 |
| 里程碑与软件单日纪录 | 按软件累计焦点，档位 10 / 50 / 100 / 500 / 1000 / 6666 小时，记录达到的最高一档和累计首次越过它的日期；只列累计焦点满 1 小时的软件，最多 30 个。“单个软件单日焦点最长”按全部历史。不做“最长一次连续使用”：会话包含托盘运行，常驻软件一次会话能连续好几天。 |
| 软件来去 | 按每个软件有窗口（`foreground_seconds > 0`）的首末日期。近 30 天（含今天）里首次有窗口、且晚于软件明细起点的是新面孔；最后一次有窗口在这 30 天之前的是 30 天未打开。全部历史累计窗口不满 1 分钟的软件两边都不计入，挡掉安装包和临时程序。 |
| 统计页与成就页的隐藏软件 | 默认不计入排行、开着没用、会话、里程碑、软件单日纪录和软件来去；打开“包含隐藏软件”开关后计入。机器级数字不变。 |
| 导出的区间汇总与每日明细（v0.4.3） | 只读命令 `get_statistics_export(start, end, include_hidden)`，区间校验和错误同 `get_statistics_summary`。焦点、窗口读 `get_statistics_summary` 用的同两张日表，后台读 `daily_software_runtime_usage.background_seconds`（软件页的后台口径）。`software` 列出区间内焦点、窗口或后台任一项大于 0 的软件，不截到 20 个；`使用天数` 是区间内焦点 ≥ 300 秒（`STREAK_MIN_ACTIVE_SECONDS`）的日子数，只有窗口或只有后台的日子不算。`days` 是每个日期 × 软件里有非零值的行，按日期升序、焦点降序、显示名排。区间汇总的排名、开着没用、打开次数、平均单次、最长单次仍取页面 `StatisticsSummary` 的三张台账，台账上没有的留空；有排名的行在前、按排名排（稳定排序 `rank ?? Infinity`），其余按导出顺序（焦点降序、窗口降序、显示名）接在后面；`rank_software` 和统计页不变。 |
| 日报海报（v0.4.3） | 读概览当前显示那天的 `get_dashboard_summary`，所以隐藏软件照概览的规则不列。大字是那天的活跃小时（一位小数），进度条是活跃 ÷ 记录，夹在 0 到 1，记录为 0 时为空条。托盘最多三个软件：按当天活跃秒数排，同分按运行秒数、再按显示名；那天全部软件都没有活跃时间时改按运行时长排、显示运行小时。今天写“今日活跃”，往日写“当日活跃”。 |
| 成就海报（v0.4.3） | 只读命令 `get_milestone_software(include_hidden)`：沿用成就页里程碑的档位（`MILESTONE_HOURS`）和达到日期（累计焦点首次越过最高一档的那天），但不截到 30 个；只列至少到 10 小时一档的软件，按档位降序、累计焦点降序、身份键排。海报上的“使用 N 天”是全部历史里焦点 ≥ 300 秒的日子数，“累计专注”是全部历史焦点。默认选中达到日期最晚的软件，同一天按列表顺序。 |
| 时间轴段 | `timeline_segments`：每个 tick 认可的秒数按本地日期块写入，与日汇总同一事务。焦点身份、活跃状态和日期都没变就延长上一行；变了，或遇到长间隔、时钟回拨、重启、跨午夜，就新开一行并记下原因。焦点键与软件页活跃同源，没有可记录的前台软件时为空；隐藏软件照记。时刻是毫秒精度的 UTC。 |
| 窗口段 | `timeline_window_spans`：每个软件身份有任务栏窗口（与 `foreground_seconds` 同源）的时段；托盘和后台不记。焦点、活跃切换不拆行；长间隔、回拨、重启、跨午夜新开一行。 |
| 时间轴等式 | 升级当天之后的每一天（`day_status = collected`）：段秒数之和 = `recorded_seconds`（= `tracker_uptime_seconds`）；活跃段之和 = `active_seconds`；每个身份的焦点段之和 = `focused_seconds`；每个身份的窗口段之和 = `foreground_seconds`。可以合理不等的情况：升级当天只有升级之后的部分；身份合并后单日超过 24 小时的汇总被封顶，段不封顶；焦点为空的段只进前两式；窗口式没有机器级对应，同一时刻可以有多个软件开着窗口。 |

概览按显示名称合并，软件页按身份汇总；两者来源、分组和后台口径不同，不能要求总数无条件相等。锁屏不等于睡眠，本轮未改变锁屏期间的运行口径。
