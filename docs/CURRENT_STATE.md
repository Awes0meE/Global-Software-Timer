## 统计口径：按当前代码解释

| 显示或指标 | 实际判定与来源 |
| --- | --- |
| 概览软件运行时长 | `usage_sessions` 的区间合并；会话要求被分类为可记录、非辅助进程且具有可见顶层窗口。关闭会话用 `ended_at`，未关闭会话用 `last_heartbeat_at`。不是所有后台进程存活时间。 |
| `前台运行` / 软件页前台秒数 | 符合条件的进程具有可见顶层窗口，不要求它拥有键盘焦点；多个软件可以同时属于这一状态。 |
| `后台运行` / 软件页后台秒数 | 已知可执行文件仍被扫描到，但只剩无可见窗口或辅助进程状态；按软件身份累计。 |
| 概览“今日记录” | tracker tick 时长累计到 `daily_system_usage`；按 tick 当时的本地日期入账。 |
| 概览“今日活跃” | tick 时键鼠空闲未超过五分钟时累计机器级活跃秒数。 |
| 概览软件活跃秒数 | 在键鼠活跃条件下，归属于已识别的 Windows 前台 PID，写入 `daily_app_usage`。 |
| 软件页“活跃” | 已识别软件拥有 Windows 前台焦点时累计 `daily_software_focus_usage`，不以键鼠空闲作为门槛。 |
| 隐藏软件 | 保留历史、继续记录；过滤默认软件列表、排行和分布，不扣除机器级记录/活跃秒数。 |
| 历史兼容 | 软件页使用按身份的前台/后台日汇总，并对拆分记录开始前的旧会话做兼容回退；旧会话没有可恢复的完整焦点历史。 |

证据入口：`src-tauri/src/tracker.rs`、`process_source.rs`、`foreground.rs`、`storage.rs`、`commands.rs` 和 `lib.rs`。概览按显示名称合并会话，软件页按软件身份汇总；两个页面不仅数据来源不同，分组与后台时间口径也不同，不能直接认定总数应当相等。

## 外部报告逐项核对

| 报告项 | 核对结论 | 实施前必须处理的细节 |
| --- | --- | --- |
| 1. 长间隔计时 | 确认 `f00093a` 曾有 60 秒上限，且是当前历史的祖先；现有 tracker 和测试中缺失该保护。`lib.rs` 使用 `last_tick.elapsed()`，会话没有长间隔切断。 | 上限只限制 tick 累计，不会修复跨睡眠的会话区间。增加可控时间测试，覆盖长间隔、跨日、时钟回拨；睡眠实机现象和移除保护的具体提交尚未定位。不要把所有锁屏时间都等同于睡眠。 |
| 2. 写入膨胀 | 确认 `scan_once` 对持续运行的软件写会话心跳和 `AppHeartbeat`；整轮没有事务。 | 报告“除恢复外全是自动提交”不准确：启动、停止及名单批量添加也已有局部事务。整轮事务需要重构边界，不能直接套一层导致嵌套 `BEGIN`。同一可执行文件多个可见 PID 还可能重复写心跳。 |
| 3. 读取竞争 | 确认 summary 与采集共用 mutex，概览读取全部会话，前端每五秒轮询。 | 查询包含 `upsert_software_identity_for_app`，需先移走写入才能使用只读连接；同一查询返回终身累计，不能简单加“仅本日”条件。锁竞争是风险，尚无耗时/漏采基准。 |
| 4. 单一事实来源 | 确认会话与每日汇总并存，但不是完全同口径的重复账本。 | 当前会话不能重建后台秒数或焦点秒数。新事实模型应先补足状态区间，并保留无法重建的历史汇总；禁止直接删掉旧汇总。 |
| 5. 迁移与安全 | 确认 `CREATE TABLE IF NOT EXISTS` + 列检查，未见 `user_version` 迁移框架；启动初始化错误会触发 `expect`。 | 在任何删历史或压缩动作前，设计一致性备份、失败恢复与旧库测试。错误不全是损坏，不能把权限/锁冲突/磁盘不足一律当坏库后重建。 |
| 6. 软件身份 | 普通软件使用规范化路径，WPS 有 `known:wps-office` 合并特例，升级路径分裂风险存在。 | `apps` 与 `software_identities` 行数不同不能证明重复：本来就允许多对一。发布者和产品名可作为信号，不能单独证明两个组件应合并。 |
| 7. 分类规则 | 确认 classifier 中存在硬编码规则。 | 当前已利用可见窗口和辅助进程标志，不是只看名字。规则数据化与用户纠错是后续设计，不是已完成能力。 |
| 8. 事件采集 | 确认五秒扫描与直接 `GetForegroundWindow` PID 获取；未见 UWP 宿主子窗口解析。 | 先复现具体 Windows 应用的归属错误，再决定事件监听、宿主解析与轮询兜底方案；尚未做实机验证。 |
| 9. UI 与口径 | 确认两个“活跃”定义不同，“正在记录”是固定文案，未完成入口仍存在。 | 两种活跃定义来自已批准的软件页规格；优先清楚解释，改变计算方式需重新设计。已有空列表状态与活跃说明弹层，不应记作完全缺失。 |
| 10. 日志与发布 | 确认使用 `eprintln!`、`csp: null`；未实现报告建议的日志导出、自动更新与备份恢复功能。 | 安装包未签名是现有发布文档记录，本轮未检查二进制。自动更新/签名属于独立设计，不能默认启用网络检查或承诺成本。 |

## 报告中不能直接作为事实的结论

- 报告中的本机数据库规模、行数与观测时间范围已从发布副本中移除；本轮未读取生产数据库，完整原文仅保存在本地。
- `recovered = 1` 表示启动时发现未关闭会话，不等于崩溃次数。目前托盘退出直接调用 `app.exit(0)`，未见统一会话关闭流程，正常退出也可能留下待恢复会话。
- “合并 backup 分支冲掉上限”仍是原因推测；只确认旧提交存在且当前实现没有保护。
- 每次写入的实际 fsync 成本、运行时卡顿、压缩后能否降至几 MB 都需要测量，不能作为已经验证的收益。
- `synchronous=NORMAL`、增量 vacuum、定期 checkpoint、事件保留天数是可评估选项；需要明确断电持久性、磁盘空间和历史保留要求，再决定是否采用。

## 建议推进顺序与验收目标

这些是下一阶段的候选工作，不是本轮已批准或已实现的修复。

1. **计时正确性**：恢复长 tick 保护、处理会话间断，并加上长睡眠、跨日、回拨、正常退出/异常恢复的确定性回归测试。明确正常后台运行与锁屏语义。
2. **新增写入止增 + 安全迁移基础**：减少冗余心跳事件、统一 tick 事务及内存状态失败处理；建立版本迁移和可恢复备份。先在脱敏测试库验证，再考虑历史事件清理与压缩。
3. **读取路径**：移除查询中的写入、缩短 tracker 锁持有时间；保持今日与终身统计等价，并在大样本库上测查询耗时及并发读取表现。
4. **统计与身份设计**：明确唯一事实模型可表达的状态、不可重建历史的保留方法和身份合并边界。保持隐藏名单及 WPS 合并行为。
5. **产品与发布**：术语、采集健康状态、日志、CSP、发布脚本失败处理；规则数据化、事件采集、签名和更新单独评估。
