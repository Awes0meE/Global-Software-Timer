v0.4.0 只改外观：侧栏和各页顶层面板是一层半透明玻璃（每页最多 6 个模糊层、不嵌套），读数是哑光墨水屏（像素字只在屏内），表盘外加 96 条刻线，概览「今日记录」「今日活跃」两个大号读数后面留一层上一次显示值的淡残影。后端只多两处只读改动：命令 `get_transparency_effects_enabled` 读 Windows「透明效果」开关（HKCU，不保存），关掉时面板改为不透明；`get_dashboard_summary` 多返回 `usage_date`（今日读数所属的本地日期），日期变了，或同一天里读数变小，残影就不画，窗口藏在托盘或停在别的页面时跨天也一样。不改采集，口径表不变。设计见[规格](./superpowers/specs/2026-11-22-glass-eink-redesign-design.md)。

## 桌面界面与数据库兼容性

软件页沿用 v0.1.5 的稳定身份键。v0.1.5 起库版本为 2；v0.3.1 升到 3，只新增 `timeline_segments`、`timeline_window_spans` 两张表，不改旧表、不回填历史，升级在一个事务里完成，失败整体回滚。升级后的库不能再被 v0.3.0 及更早版本打开。

概览、软件、后台、统计和成就页的每一行只带一个短图标地址（`gsticon` 协议），图片由后台线程按需读取：可执行文件按内嵌的最大尺寸（最多 256px）读取，再统一缩放成 96px；Windows 绘制出的预乘透明度会被还原，避免边缘发暗；老式无透明通道的图标改用黑底、白底各绘制一次来求出遮罩，保留黑色描边。获取失败的图标冷却 60 秒后，由下一次摘要刷新换一个地址重新读取。读到的图标存进 `%LOCALAPPDATA%\com.globalsoftwaretimer.app\icons\`（以路径、文件大小和修改时间区分，90 天前写入的文件启动时清理），重启后直接读盘。图片到达前或软件没有图标时显示首字。此次实测与本地验证边界见[界面整改记录](./ui-redesign-backlog.md)。会话区间仍按原始数据计算。

## 统计口径

| 指标 | 定义 |
| --- | --- |
| 概览软件运行 | 被分类为可记录的非辅助进程拥有任务栏式窗口或被识别为托盘软件时建立会话，按会话区间合并计算。不是所有进程存活时间。 |
| 最常用 | v0.2.3 起取今日活跃时长最多的软件；今天没有活跃时长时取今日运行时长最多的软件；今天没运行过则为空。台账仍按累计时长排序。 |
| 前台运行 | 符合条件的进程拥有任务栏式应用窗口（可见、无可见所有者、非工具/不激活/穿透浮层、未被自身隐藏、非零尺寸），不要求键盘焦点；多个软件可同时处于此状态。UWP 框架窗口归属到其承载的应用进程。 |
| 托盘运行 | 无任务栏窗口，但可执行文件登记在 `HKCU\Control Panel\NotifyIconSettings`（Win11）且进程在当前用户会话中。与前台运行一样建立运行会话；软件页计入窗口外（后台）时长。注册表会记住曾经显示过的图标，因此是近似判断；Win10 无此数据，退回原行为。 |
| 后台运行 | 已知可执行文件仍存在，但既无任务栏窗口也无托盘图标，或只剩辅助进程；不建立运行会话，软件页按身份累计。 |
| 后台页 | 非 Windows 系统进程中既无窗口也无托盘图标者，按软件族分组；由可见软件（含经辅助进程）启动的子进程归属该软件、不列出。每日记录后台时长、CPU 核心秒、内存峰值与进程数（`daily_background_usage`，库版本 2），并显示最近一次采样的实时 CPU/内存。 |
| 概览今日活跃 | 机器键鼠空闲不超过五分钟时的计入秒数；概览软件活跃再归属到已识别的前台 PID。 |
| 软件页活跃 | 已识别软件拥有 Windows 前台焦点时的计入秒数，不受键鼠空闲门槛影响。 |
| 软件身份 | 按去版本号的路径族归并：商店应用按包族合并，版本号目录与哈希目录忽略。启动时把旧的逐版本身份及其汇总、标记合并，单日合并结果不超过 24 小时。 |
| 隐藏软件 | 继续记录，过滤默认软件汇总、排行与分布，不扣除机器级总数。 |
| 历史兼容 | 软件页保留拆分记录开始前的会话回退；新会话在观察时即写入拆分边界，避免零计入恢复或小数秒采样触发重复累计。旧数据缺失的焦点/后台历史不能凭空重建。 |
| 统计页机器数字 | 每日趋势、活跃率、环比，以及作息里的工作日 / 周末日均活跃和日均开机时长，读 `daily_system_usage` 的记录、活跃（五分钟键鼠空闲门槛）与开机时长（`tracker_uptime_seconds`）。每日趋势和工作日 / 周末日均活跃把区间内没有数据的日子补 0（页面注“空白日计入”）；日均开机时长只除以有记录（记录时长大于 0）的日子（页面注“按有记录的 N 天”）。不受隐藏软件影响。 |
| 作息最早 / 最晚记录 | 不读 `daily_system_usage`：取 `daily_software_runtime_usage` 中当天有窗口（`foreground_seconds > 0`）的行的最早 `first_recorded_at` 和最晚 `last_recorded_at`，再对区间内有值的日子取本地时间中位数。只算有窗口时间的日子；软件明细起点之前的日子没有值；隐藏软件始终计入，“包含隐藏软件”开关不过滤。 |
| 统计页软件数字 | 区间排行按软件焦点（`daily_software_focus_usage`）排名，与软件页活跃同一口径；保留焦点或窗口大于 0 的软件，最多 20 个，同分按显示名。名次与上一个等长区间比较，上一区间不可比时不标名次变化和“新上榜”。 |
| 开着没用 | 只算有任务栏窗口的时间（`daily_software_runtime_usage.foreground_seconds`），不算托盘和后台时间。区间内窗口不少于 5 小时、焦点低于窗口的 5% 才上榜，按窗口减焦点的时长排序。 |
| 统计页会话 | `usage_sessions` 经身份成员表归到软件身份，按开始时间的本地日期落入区间；已关闭会话用记录的时长，未关闭会话用最后心跳减开始时间。会话包含托盘运行。 |
| 区间与软件明细起点 | 数据起点取 `daily_system_usage` 的最早日期，软件明细起点取 `daily_software_runtime_usage` 的最早日期（本机为 2026-05-29 和 2026-06-18）。自定义区间最长 366 天，不早于数据起点。上一区间早于数据起点时机器对比显示“无对比”，早于软件明细起点时排行不比名次。明细起点之前的日子标“无软件明细”，软件数字不计入，也不当作 0。 |
| 热力图与连续天数 | 按机器活跃（`daily_system_usage.active_seconds`）。当天活跃不到 5 分钟按“没用”算，只为过滤开机看一眼的噪声，不是目标。连续天数和“活跃最长的一天”按全部历史，不受热力图范围（90 / 180 / 365 天）和隐藏开关影响；今天还没满 5 分钟时，当前连续从昨天往回数。 |
| 里程碑与软件单日纪录 | 按软件累计焦点，档位 10 / 50 / 100 / 500 / 1000 / 6666 小时，记录达到的最高一档和累计首次越过它的日期；只列累计焦点满 1 小时的软件，最多 30 个。“单个软件单日焦点最长”按全部历史。不做“最长一次连续使用”：会话包含托盘运行，常驻软件一次会话能连续好几天。 |
| 软件来去 | 按每个软件有窗口（`foreground_seconds > 0`）的首末日期。近 30 天（含今天）里首次有窗口、且晚于软件明细起点的是新面孔；最后一次有窗口在这 30 天之前的是 30 天未打开。全部历史累计窗口不满 1 分钟的软件两边都不计入，挡掉安装包和临时程序。 |
| 统计页与成就页的隐藏软件 | 默认不计入排行、开着没用、会话、里程碑、软件单日纪录和软件来去；打开“包含隐藏软件”开关后计入。机器级数字不变。 |
| 时间轴段 | `timeline_segments`：每个 tick 认可的秒数按本地日期块写入，与日汇总同一事务。焦点身份、活跃状态和日期都没变就延长上一行；变了，或遇到长间隔、时钟回拨、重启、跨午夜，就新开一行并记下原因。焦点键与软件页活跃同源，没有可记录的前台软件时为空；隐藏软件照记。时刻是毫秒精度的 UTC。 |
| 窗口段 | `timeline_window_spans`：每个软件身份有任务栏窗口（与 `foreground_seconds` 同源）的时段；托盘和后台不记。焦点、活跃切换不拆行；长间隔、回拨、重启、跨午夜新开一行。 |
| 时间轴等式 | 升级当天之后的每一天（`day_status = collected`）：段秒数之和 = `recorded_seconds`（= `tracker_uptime_seconds`）；活跃段之和 = `active_seconds`；每个身份的焦点段之和 = `focused_seconds`；每个身份的窗口段之和 = `foreground_seconds`。可以合理不等的情况：升级当天只有升级之后的部分；身份合并后单日超过 24 小时的汇总被封顶，段不封顶；焦点为空的段只进前两式；窗口式没有机器级对应，同一时刻可以有多个软件开着窗口。 |

概览按显示名称合并，软件页按身份汇总；两者来源、分组和后台口径不同，不能要求总数无条件相等。锁屏不等于睡眠，本轮未改变锁屏期间的运行口径。

## 剩余工作与报告修正

- **历史数据清理和备份**：本轮未打开或修改生产数据库，未执行删除、VACUUM、保留期清理、synchronous 调整或自动坏库隔离。先建立可恢复备份、脱敏样本和实测迁移，再处理历史数据；生产库规模与行数未在本轮重测，也未随报告发布。
- **查询复杂度**：已解除长时间占用采集锁；v0.2.2 起原生首屏有合成大库基准（见[桌面验收](./desktop-qa.md)）。终身累计仍需扫描会话，物化汇总仍待做。
- **统一账本**：必须先设计可表达后台/焦点状态的事实模型；不能删掉当前会话无法重建的日汇总。
- **Windows 生命周期**：已处理普通 Tauri 退出与采样中断；系统电源/会话通知、关机截止时序及真实睡眠/休眠测试仍需专门验证。
- **产品与识别**：软件升级路径合并、UWP 宿主识别、托盘软件识别与后台进程页已随 v0.1.5 发布；Win10 托盘识别、规则数据化、事件采集、时间轴页（数据已采集，页面待 v0.5.0）与术语交互设计仍待做。当前已有空列表和活跃说明，不属于完全缺失。
- **统计与成就**：星期 × 小时习惯图尚未实现，以后可从逐段数据派生（v0.3.1 起采集，只能从采集起点算起）；热力图点某天跳到时间轴要等时间轴页；导出与场景分类另开需求。
- **可观测性与分发**：v0.2.2 起侧栏显示最近一次采样的真实状态；持久化日志、CSP、导出恢复、签名和自动更新仍待独立实现，未启用任何新网络功能。
- 报告的“除恢复外全部自动提交”在旧基线也不准确；启动/停止/名单操作原本已有局部事务，本轮补齐了整轮原子性。
- 旧 `recovered=1` 不能等同于崩溃次数，旧版普通退出也可能留下会话。`apps` 与身份表行数不同也不证明重复，两者允许多对一。
- 已确认 `f00093a` 的计时保护在旧基线缺失，但未证明是报告推测的某次 backup 合并导致。
