## 桌面界面与数据库兼容性

软件页沿用 v0.1.5 的稳定身份键与 schema 2。已有 v0.1.5 数据库无需新增迁移，旧库沿用原迁移流程。

概览、软件和后台页从进程内缓存取图标，首次缺失时用首字占位，由后台线程读取 Windows 图标并在下一次可见刷新时显示。此次实测与本地验证边界见[界面整改记录](./ui-redesign-backlog.md)。会话区间仍按原始数据计算。

## 已完成修复

| 项目 | 修复后的行为 |
| --- | --- |
| 长间隔与时钟回拨 | 观察间隔超过 10 秒或墙上时钟倒退时，在上次可靠心跳处关闭旧会话，再重新识别运行软件；不把未知间隔记入每日累计。保留 60 秒 tick 防御上限。 |
| 跨午夜 | 注入带时区的观察时间，将获准计入的秒数按当地日期拆分到机器、软件运行、机器活跃和软件焦点汇总。 |
| 心跳写入 | 不再新增 `AppHeartbeat` 事件；同一可执行文件每次扫描只更新一次会话心跳，同时保留全部可识别 PID 的焦点映射。旧心跳历史仍保留。 |
| 原子性 | scan/tick 使用可嵌套 savepoint；会话、事件、身份与日汇总全部成功后才替换内存状态，失败同时回滚数据库与 tracker 状态。 |
| 正常退出 | Tauri 正常退出回调按可靠心跳关闭会话并停止后续采集。强制终止仍由下次启动恢复。 |
| 迁移基础 | `user_version=1` 表示版本化基线；旧库结构升级和版本标记在事务中完成，失败回滚，拒绝未知的更高版本。启动维护身份缓存，保留历史和设置，添加查询索引。 |
| 查询连接 | 概览和软件页使用独立只读连接及一致性读事务；仅复制运行状态时短暂持有 tracker 锁。查询不再写身份缓存。终身会话区间合并与历史兼容逻辑保留。 |
| 界面刷新 | 页面可见时轮询，document 隐藏后停掉轮询，恢复可见时刷新；不积压计时器请求。软件页的过期成功/失败响应不能覆盖用户操作后的新列表。 |
| 发布脚本 | 检查或打包命令返回非零状态时立即停止，不再继续复制旧安装包；两条失败路径已有自动回归测试并接入本地 check 与 CI。 |

## 统计口径保持不变

| 指标 | 定义 |
| --- | --- |
| 概览软件运行 | 被分类为可记录的非辅助进程具有可见顶层窗口时建立会话，按会话区间合并计算。不是所有进程存活时间。 |
| 前台运行 | 符合条件的进程拥有任务栏式应用窗口（可见、无可见所有者、非工具/不激活/穿透浮层、未被自身隐藏、非零尺寸），不要求键盘焦点；多个软件可同时处于此状态。UWP 框架窗口归属到其承载的应用进程。 |
| 托盘运行 | 无任务栏窗口，但可执行文件登记在 `HKCU\Control Panel\NotifyIconSettings`（Win11）且进程在当前用户会话中。与前台运行一样建立运行会话；软件页计入窗口外（后台）时长。注册表会记住曾经显示过的图标，因此是近似判断；Win10 无此数据，退回原行为。 |
| 后台运行 | 已知可执行文件仍存在，但既无任务栏窗口也无托盘图标，或只剩辅助进程；不建立运行会话，软件页按身份累计。 |
| 后台页 | 非 Windows 系统进程中既无窗口也无托盘图标者，按软件族分组；由可见软件（含经辅助进程）启动的子进程归属该软件、不列出。每日记录后台时长、CPU 核心秒、内存峰值与进程数（`daily_background_usage`，库版本 2），并显示最近一次采样的实时 CPU/内存。 |
| 概览今日活跃 | 机器键鼠空闲不超过五分钟时的计入秒数；概览软件活跃再归属到已识别的前台 PID。 |
| 软件页活跃 | 已识别软件拥有 Windows 前台焦点时的计入秒数，不受键鼠空闲门槛影响。 |
| 软件身份 | 按去版本号的路径族归并：商店应用按包族合并，版本号目录与哈希目录忽略。启动时把旧的逐版本身份及其汇总、标记合并，单日合并结果不超过 24 小时。 |
| 隐藏软件 | 继续记录，过滤默认软件汇总、排行与分布，不扣除机器级总数。 |
| 历史兼容 | 软件页保留拆分记录开始前的会话回退；新会话在观察时即写入拆分边界，避免零计入恢复或小数秒采样触发重复累计。旧数据缺失的焦点/后台历史不能凭空重建。 |

概览按显示名称合并，软件页按身份汇总；两者来源、分组和后台口径不同，不能要求总数无条件相等。锁屏不等于睡眠，本轮未改变锁屏期间的运行口径。

## 剩余工作与报告修正

- **历史数据清理和备份**：本轮未打开或修改生产数据库，未执行删除、VACUUM、保留期清理、synchronous 调整或自动坏库隔离。先建立可恢复备份、脱敏样本和实测迁移，再处理历史数据；生产库规模与行数未在本轮重测，也未随报告发布。
- **查询复杂度**：已解除长时间占用采集锁，但终身累计仍需扫描会话；物化汇总和大库性能基准仍待做，未宣称查询性能提升倍数。
- **统一账本**：必须先设计可表达后台/焦点状态的事实模型；不能删掉当前会话无法重建的日汇总。
- **Windows 生命周期**：已处理普通 Tauri 退出与采样中断；系统电源/会话通知、关机截止时序及真实睡眠/休眠测试仍需专门验证。
- **产品与识别**：软件升级路径合并、UWP 宿主识别、托盘软件识别与后台进程页已在 `fix/process-grouping` 完成；Win10 托盘识别、规则数据化、事件采集、时间轴与术语交互设计仍待做。当前已有空列表和活跃说明，不属于完全缺失。
- **可观测性与分发**：固定“正在记录”文案、持久化日志、CSP、导出恢复、签名和自动更新仍待独立实现，未启用任何新网络功能。
- 报告的“除恢复外全部自动提交”在旧基线也不准确；启动/停止/名单操作原本已有局部事务，本轮补齐了整轮原子性。
- 旧 `recovered=1` 不能等同于崩溃次数，旧版普通退出也可能留下会话。`apps` 与身份表行数不同也不证明重复，两者允许多对一。
- 已确认 `f00093a` 的计时保护在旧基线缺失，但未证明是报告推测的某次 backup 合并导致。
